# Neon Sign Sites

We rebuild weak websites of US local service businesses (lawn care, mobile detailing, ...) and offer the new site by email, with a free preview. Owner: Alon (sole proprietor in Israel, עוסק פטור). Store Passport (repo `kelon33/site-translator`) is a separate business: don't touch it from here.

## Offer (keep the site, terms, emails and previews consistent with it)
- **Own it:** $299 one-time. Hosting and SSL included for the first year, then $49/year. Changes $25 each, or $19/month care.
- **Monthly:** $0 to start, $49/month. First month paid at launch, 3-month minimum, then cancel anytime. Up to 2 small edits a month (text, photos, prices, hours). Switch to owning for $299 anytime.

## Repo and publishing
- `site/` is neonsignsites.com (home, terms, privacy, 404). `generator/` builds a customer site from `demos/<slug>/site.json`, with one kit per trade (`kits/detailing.mjs` dark/glossy, `kits/lawn.mjs` bright/green). `pipeline/` goes from a lead to a preview. `leads/` holds lead research.
- **Every push to `main` goes live in about a minute.** Cloudflare Workers Builds runs `node deploy.mjs --dry`, then `npx wrangler deploy` (`wrangler.jsonc`). Previews are at `neonsignsites.com/p/<slug>/`, never indexed (robots.txt, X-Robots-Tag, meta tag).
- `npm test` must pass before pushing.
- The Cloudflare token on the environment (proxy-injected for api.cloudflare.com) has Pages Edit, Account Settings Read and DNS Edit (neonsignsites.com zone). It has **no Workers permissions**: Worker settings and custom domains are done by Alon in the dashboard. Wrangler uploads don't work from a cloud session (the proxy replaces wrangler's upload token), so use git pushes.

## Pipeline
- `npm run find -- --trade lawn,detailing --city "Austin, TX"` finds new leads with Google Places (Text Search only, a minimal field mask, next page only while it pays off), checks their sites and emails for free, and writes `leads/found-<date>.json`. `--dry` shows the plan and worst-case cost first. Every request is counted in `leads/places-usage.json` (commit it) against `config.json` `places.monthlyRequestCap` (600 ≈ $21 at list price); a search already run is skipped unless `--again`. Needs `GOOGLE_PLACES_API_KEY` (or `NEON_GOOGLE_PLACES_API_KEY`) in the environment. The search and the site check can run apart: `--no-check` in the `neon-sign-sites` environment (has the key; its network must allow `places.googleapis.com`), then `npm run find -- --check leads/found-<date>.json` in `neon-sign-sites builder` (open network). If nearly every site fails to load, the check stops instead of marking them broken. Each trade searches several phrases (`TRADES` in `pipeline/find.mjs`; `--phrases 1` for the main one only, worst case 3 requests per phrase and city). Sites come out as `weak site` (main pitch), `decent site` (works but has clear gaps, listed in `improvements`: a separate, second pitch) or `strong site` (not pitched); `--check <file> --again` re-checks a file for free. Every save sorts the file weak → decent → strong (then broken, not checked) and writes `leads/found-<date>.md`, a readable copy with one section per category and a count per trade (commit it with the .json).
- `npm run find -- --trade lawn,detailing --next 3` takes the next unsearched cities from `leads/cities.json` (ordered so consecutive cities are in different regions). Test trades (`TRADES` entries with `test: true`: pressure, pool, windows, and small one-person trades such as petwaste, sprinkler, stump, sod, lights, boat, rv, dent, windshield, handyman, painting, junk, grooming) are search-only, to measure their weak-site rate; `npm run batch` never builds them until the trade is promoted (drop `test`). For one-person trades use `--min-reviews 5` and smaller towns. Promoted trades that borrow a kit (`dent` → detailing, `lights` → lawn) get their own default wording from `TRADE_WORDS` in `pipeline/copy.mjs`, so no lawn or detailing leftovers show; add an entry there when promoting another one.
- `npm run batch -- --file leads/found-<date>.json --count 5 [--dry]` builds previews for the best leads (email, kit, not built, not on do-not-contact; weak sites first, then decent, trades in turn) with `npm run lead -- --place <id>`, and writes `leads/batch-<date>.md` to review them by. Review every preview as usual.
- `npm run queue -- --plan` writes `outbox/<date>.md`: today's emails in full, for Alon's approval, within each mailbox's daily limit (`config.json` `sending.mailboxes`: no `start` date means it sends nothing). It never sends. After an approved email is sent: `npm run queue -- --record <slug> --from <mailbox>` (log in `leads/sent.json`, commit it). It refuses neonsignsites.com mailboxes, businesses already emailed, do-not-contact entries, and planning while there is no postal address.
- `verify()` also drops trust claims their site does not make (licensed, insured, guarantee, family-owned, owner does the work, no subcontractors, same-day, 24/7...) and notes the AI wrote to itself ("the site says..."). Decent-site emails name the gap the site check found. When a preview ends up with no gallery (fewer than 4 usable photos of their work), it is still built and sent, with the photo pitch: `site.json` `pitch: "photos"`, and the email says their site shows almost none of their work and asks for 5 or 6 job photos to finish it. `npm run batch -- --place <id>,<id>` builds exactly those leads.
- `npm run lead -- --lead "<name>"` reads their site, picks photos and logo, writes the wording, renders the site and writes `preview.html`, `desktop.jpg`, `phone.jpg`, `email.txt` and `check.txt` in `demos/<slug>/`. `--no-ai` uses the free kit wording; `--fresh` ignores an existing hand-written `site.json` (otherwise its wording is kept).
- The AI wording needs `ANTHROPIC_API_KEY` or `NEON_ANTHROPIC_API_KEY` (an environment variable; the cloud environment has the NEON_ one). The model is `config.json` `aiModel` (Sonnet 5.5, a few cents a lead; Haiku 5.5 is the cheap option). `verify()` drops reviews not on their site word for word and any number not in their site text or Google facts.
- Always look at `desktop.jpg`/`phone.jpg` and `check.txt` before showing a preview to Alon.
- `demos/ericks-auto-detailing` and `demos/lawn-sculptures` are hand-written: don't regenerate their wording.

## Rules that must not break
- **Nothing is sent without Alon's explicit approval of the exact text and link.** Show him each email in full first.
- Previews use only the business's own public content (their website; rating and review count from Google). Never invent reviews, prices, years, guarantees or licences. Never copy Google listing photos or review texts into a site (Google's terms).
- US cold email (CAN-SPAM): our postal address and an opt-out line in every email; honour every "no": add them to `do-not-contact.json` (email, and domain or name) the day they reply; the pipeline refuses any lead on it, and no entry is ever removed. No cold SMS (TCPA).
- Cold email goes from the `.net` (later `.co`) mailboxes, **never from neonsignsites.com**. The .com is the brand: the site, hello@ and alon@ (aliases of alon@neonsignsites.net).
- Start slow: 5 emails a day from alon@neonsignsites.net in the first week, 10 from week 2, more only after the mailboxes are warmed up.
- Google Places API spend stays under about $25 a month in total.
- Never ask for secrets in chat. Never commit secrets. The repo stays private.
- Commit messages end with the attribution lines the session gives.
